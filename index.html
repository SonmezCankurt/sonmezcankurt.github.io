Chaosborne

PC roguelike auto-battler · Unity 6 · Feb 2026 – Present · Gameplay and systems programmer in a 2-person team

Shipped a public Steam playtest and ran a booth with hands-on player demos at Gaming Istanbul (GIST) 2026. Below are the systems I built, each with the problem, the approach and the trade-off.

Data-driven combat effect engine

Problem Item cooldowns, item triggers and passive relics each described effects differently, so every new item needed code.

Approach I rewrote the engine around one serializable effect model (19 effect types, 16 target options, AND/OR target filters) that all three share. Shared helpers own the target and filter rules, one method writes every stat buff, and random targeting reuses list buffers to avoid per-cast allocations. It drives 392 effects across 230 items.

Trade-off A single model has to stay small, so validity rules live in authoring tools instead of in the model itself.

C# · ScriptableObjects · data-driven design

Item trigger engine with loop safeguards

Problem Reactions can trigger other reactions ("when you Slow, gain Rot", "when you Rot, Speed an item"...), which can loop forever.

Approach The engine reacts to 11 combat events and has 3 safeguards: an allow-list enforced in OnValidate that keeps the trigger graph acyclic (the longest allowed chain is Slow → Rot → Speed → Chaos → Recovery), a guard that lets each effect fire once per chain, and a recursion depth limit with warning logs.

Trade-off Some effect combinations are blocked by design; "first N times per fight" effects are bounded by per-fight limits instead.

Event-driven architecture · C# events · graph design

Editor tooling and content pipeline

Problem A 2-person team cannot keep hundreds of assets consistent by hand.

Approach Custom inspectors and property drawers show only the fields that matter. OnValidate rules snap invalid data to a legal state and log a readable warning, and a pre-build pass re-validates every asset. Idempotent builders create 23 shop types, 30 events and 26 fortunes from code, and a generator produced 800 enemy fight variants across 16 difficulty levels.

Trade-off OnValidate only runs in the editor, so the pre-build pass is a required manual step.

Unity Editor scripting · tools · procedural generation

Localization and data-driven tooltips

Problem Hand-written tooltips drift from real values, and Turkish needs its own casing and grammar.

Approach An editor extractor pulls player-facing text into CSV files and an importer bakes them into ScriptableObject tables (1,199 keys, English and Turkish) with live language switching. Tooltips are generated from effect data, so they show current, buffed item values; a keyword formatter adds colors and inline icons.

Trade-off Culture-aware casing (Turkish dotted and dotless I) needs invariant comparisons everywhere keys are matched.

Localization · uGUI · TextMesh Pro
